## Findings

### MINOR-1 — `[0,1]`/`[0,100]` bound checks silently accept `double.nan` (fail open)
- **Where:** `analysis_capability.dart:46` (`CapabilityReport.confidence`), `analysis_event.dart:11` (`AnalysisEvent.confidence`, base of all 7 event subtypes), `analysis_segment.dart:14` (`AnalysisSegment.confidence`), `analysis_metric.dart:98` (`AnalysisMetricResult.confidence`), `analysis_hotspot.dart:22` (`AnalysisHotspot.confidence`), plus the non-confidence magnitudes `analysis_metric.dart:18` (`PercentageMetricValue`), `analysis_metric.dart:71` (`ScoreMetricValue`), and `signal_quality_report.dart:24` (`clippedSampleRatio`/`silentRatio` — note these two are absent from that class's own `isFinite` list at lines 15-21).
- **Failure scenario:** A future producer computes `confidence = 0.0/0.0` (or any `NaN`, e.g. a divide-by-zero in a normalization step) and constructs `CapabilityReport(confidence: double.nan)`. The guard `if (confidence < 0 || confidence > 1)` does **not** fire, because in Dart `NaN < 0` and `NaN > 1` are **both false**. The invalid confidence is stored verbatim. Any downstream gate of the form `if (confidence < threshold) suppress` then evaluates `NaN < threshold == false` → the low-quality result is **not** suppressed → weak/garbage evidence is presented as certain.
- **Rule violated:** AGENTS.md §5.5 / ADR 0179 ("weak confidence must never be presented as certainty"); the round's own §5.6 ("`[0,1]`-en kívüli confidence … kontrollált hiba … csendes … NEM elfogadható"). NaN is outside `[0,1]` yet receives no controlled error.
- **Reproduction (measured, both build modes):** A standalone probe importing the shipping `public.dart` barrel by relative path (the domain graph has zero `package:` imports, so plain `dart run` needs no `pub get`) constructed each type with `double.nan`. All 8 sites printed `ACCEPTED (no throw) … fails OPEN` under **both** `dart run --enable-asserts` (test-mode) and `--no-enable-asserts` (release-APK-mode) — identical, so this is genuine release behavior, not an assert artifact. Positive controls in the same run: `confidence = +infinity` → rejected (`inf > 1` is true), `confidence = 2.0` → rejected, `ScalarMetricValue(double.nan)` → rejected (it uses `!isFinite`). So the gap is NaN-specific and idiom-specific.
- **Why MINOR not MAJOR:** latent — the feature is fully unwired (`grep -rn "import.*audio_analysis" lib/` = NONE; the only `class CapabilityReport` is this new one, and the 6 incidental grep hits were the pre-existing unrelated `SongCapabilityReport`). No producer emits confidence this round, and the §6 acceptance matrix ("Confidence-küszöb hármas") only tests finite epsilon cells (`-1e-9`, `1.0+1e-9`), so no in-round test is defeated. The bound-loosening probe below confirms the *finite* check is genuinely enforced; it is simply blind to NaN.
- **Fix direction (byte-identical to in-diff siblings):** prepend `!confidence.isFinite ||` (or `confidence.isNaN ||`) to each of the 8 range guards. The correct pattern already ships in the same diff at `analysis_metric.dart:11,37,46`, `analysis_timeline.dart:6,16`, and `signal_quality_report.dart:15-21`. MUST-fix before R04/R07 wires a confidence producer.

## NOTEs (forward-looking; no sink exists this round)

- **NOTE-1 — open `Object?` bag:** `CapabilityReport.details` is `Map<String, Object?>` (`analysis_capability.dart:44,58`), an untyped container that contrasts with the deliberately-sealed `AnalysisMetricValue`. Today it is unmodifiable and never serialized/logged (no sink), so it cannot leak. When the R03 codec or any logging is added, review whether a producer can stuff rich/raw data (e.g. sample arrays) into `details` and whether the serializer redacts it.
- **NOTE-2 — free-string fields for the future codec/logging round:** `AnalysisInputSummary.sourceName` (`String?`, `analysis_input_summary.dart:29`) can hold a filename/path; `AnalysisInsight.messageArgs` / `AnalysisWarning.messageArgs` (`Map<String,String>`) and `AnalysisProvenance.stageVersions` are free strings. All are inert now (no sink), but the R03 codec / any diagnostics path must treat these as potentially user-identifying and redact/validate before they reach a log, error message, or the network.
- **NOTE-3 — fingerprint contract is safe but unenforced (by design):** `AnalysisInputSummary.fingerprint` and `AnalysisProvenance.inputFingerprint` are plain `String` fields validated only for non-emptiness (`analysis_input_summary.dart:20-22`, `analysis_provenance.dart:19-30`). The type-level contract does **not** foreclose a safe (non-identifying, non-invertible) hash and does **not** commit to any unsafe scheme — correct for this layer (SDD §10.4; the algorithm is a later round). The hashing round must ensure it is neither a stable user identifier nor invertible to raw audio.
- **NOTE-4 — flag snapshot in provenance:** `AnalysisProvenance.featureFlagSnapshot` (`Map<String,bool>`) will capture flag state into the (future) persisted/exported document. Benign now (booleans only), but when serialized, confirm no flag name leaks account/identity signal.

## Check-by-check evidence (task axes 1–7)

1. **Raw audio never leaves device by default — PASS.** `AnalysisInputSummary` (`analysis_input_summary.dart:24-30`) carries only `source` (enum), `duration` (Duration), `sampleRate`/`channelCount` (int), `fingerprint` (String), `sourceName` (String?), `originalAudioRetained` (bool). `originalAudioRetained` defaults **`false`** (line 12) per ADR 0217. A byte-buffer sweep (`Uint8List|Int16List|Float32List|ByteData|List<int>|bytes|pcm|samples|waveform|blob`) over the new code found no raw-audio container — the only hit was `DistributionMetricValue(List<double>)` (`analysis_metric.dart:35`), a finite-checked statistical distribution of metric values, not audio. And no serialization/network sink exists to carry anything off-device regardless.
2. **No hidden network/logging of sensitive data — PASS.** Grep over the new files: zero `print`/`debugPrint`/`developer.log`/`log(`/`stderr`/`stdout`; zero `toJson`/`toMap`/`serialize`/`toString`-override/`jsonEncode`; zero `dart:io`/`dio`/`http`/`HttpClient`/`Socket`/`MethodChannel`/`Platform.`/`SharedPreferences`/`SecureStore`/`KeyValueStore`/`Supabase`. Every domain file imports only its sibling domain files — no framework/IO import at all.
3. **Fingerprint/privacy — PASS (type level).** See NOTE-3. Contract permits a safe implementation; nothing commits to an unsafe one.
4. **Weak confidence never presented as certainty — see MINOR-1.** Finite enforcement is correct and fail-closed via real `throw` (not `assert`, so it fires in the release APK). **Bound-loosening probe (task-mandated, done in this clone then reverted):** changed `analysis_capability.dart:46` `confidence > 1` → `> 2`; `flutter test analysis_document_test.dart` turned the `1.000000001` cell **red** — `Expected: throws ArgumentError / Actual: returned CapabilityReport` at test line 36 — proving the finite check has teeth. Reverted via `git checkout`; `git status` clean, HEAD unchanged. No silent clamping anywhere (all invalid finite values throw). Residual gap is NaN only (MINOR-1).
5. **Feature-flag rollout boundary — PASS.** All three flags default `false` in the constructor (`feature_flags.dart:32-34`) and are hardcoded `false` in `forEnvironment` (lines 77-79) — **not** gated on `nonProd`, so they are OFF in dev/lab/production alike. Positive fail-closed pattern observed: the metric-ID allowlist `AnalysisMetricId.known` (`analysis_metric_catalog.dart:12-19`) is a closed set and `AnalysisMetricResult` rejects any non-catalogued ID (`analysis_metric.dart:92`), tested at `analysis_metric_test.dart:42`.
